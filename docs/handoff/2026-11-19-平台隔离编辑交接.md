# 平台隔离编辑交接：v0.5 实现及复验

日期：2026-11-19。交接给下一个 agent。方案原文在 `~/.claude/plans/vivid-chasing-snowglobe.md`（阶段 0–5，已确认的四条产品决策都在里面）。

## 一句话背景

工具的成稿模型是「一份共享 Markdown → 六平台派生成稿」。右侧平台编辑器原本是**共享源稿的遮罩编辑器**，于是出现三个用户反馈：

1. 在搜狐删掉网站链接，其它平台那份也没了（改动被反解写回 `state.markdown`）。
2. 百家号删不掉带链接的段落（降级链接 → 段落被标成保护块），删掉后兼容提示仍在（提示是排版快照）。
3. 「一键检查内容」查的是错别字词表，故意删内容永远查不出来。

## v0.5 现行行为

- [工作台状态机](<../../src/app/studio-state.ts>) 以平台基线和三态补丁保护共享源稿。切平台不改稿；相同基线重排复用右侧补丁；变化后保留旧稿供查看，撤销才能使用新稿。
- [显式同步入口](<../../src/app/use-studio.ts>) 调用局部反解及[整块差异重定位](<../../src/features/preview/source-rebase.ts>)；一处无法安全写回则拒绝整次同步。右侧插图先留在当前平台，确认同步后才配对到共享源稿。无需迁移；刷新不保存改动。
- [兼容重算](<../../src/features/preview/assess.ts>) 只依据当前成稿；源稿快照无法验证则保守标记。「缺失段落」显示段号和原文摘录；原段不在成稿时「定位」明确说明，不跳邻段。发布预检保留上一次手动定位入口供改字后回到原段，但不计入最新风险。

## 容易踩的坑

1. **不要用命中片段做块回退判据**：先确认 DOM 段落身份，再用扫描时的整段文字 `context` 比较，不能用命中字符或旧段落序号证明身份。
2. **`unitIndexOf` 对表格**：`TABLE` 不在 `BODY_BLOCK_TAGS` 里，必须用「节点内部的第一个块」分支。
3. **`LocateOutcome` 是判别联合**，取 `.reason` 必须先 `outcome.status === 'unavailable'` 收窄，TS 在 `strict` 下不会自动放行。
4. **`reassessWarnings` 不要回源稿**：它只吃成稿 HTML；源稿相关的判定一律标 `source`，界面上是「重新排版确认」，不要伪造 `live`。
5. 本地起服务验证 UI 时端口用 5183 + `--strictPort`，避免和其它会话抢端口。
