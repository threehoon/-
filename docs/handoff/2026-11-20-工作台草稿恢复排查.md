# 工作台草稿恢复排查

日期：2026-11-20\
状态：已在本地工作台实现最近一篇草稿自动恢复。

## 为什么退出后内容会消失

`src/app/use-studio.ts` 在页面打开时调用 `createInitialState`。`src/app/studio-state.ts` 初始化时把原稿、平台标题和正文改动、排版结果、模板选择和图片配对设为空。项目没有把这些内容写入浏览器存储，也没有启动时读取草稿的逻辑。`README.md` 已说明工具不保存会话。

左侧配对的本地图片使用 `URL.createObjectURL` 生成的临时图片地址。实现恢复时需要一起保存图片文件的数据，重新打开后再生成可用地址。平台手改标题、正文和格式需要一并保留，仅恢复左侧 Markdown 再排版无法还原这些编辑。

## 待讨论的范围

- 单篇自动恢复：编辑后自动保存在本机浏览器，重新打开自动接回上次状态。考虑使用 IndexedDB，它能同时存文本和图片文件。稿件以实际写入成功为准显示「已保存」，写入失败时保留上一次成功保存的版本并显示失败提示。
- 多篇草稿箱：如果经常交替处理不同稿件，按篇分别保存，用户可以新建并切换稿件。这也避免导入另一篇时自动保存把前一篇覆盖掉。
- 如果需要换设备或清理浏览器后还能找回稿件，需要另外讨论可导入的备份文件或同步方式。浏览器本地保存依赖浏览器配置和访问地址。

## 已实现：最近一篇本机草稿

- 只保存到同一浏览器和网址的 IndexedDB，不上传。自动恢复原稿、成稿、平台标题和正文格式、模板、当前平台以及配对和插入的本地图片。
- 仅事务提交成功后显示「草稿已保存到本机」。存储失败时当前编辑留在页面，上一份成功提交的稿件继续保留；另一标签页已更新时不覆盖它。草稿恢复前不会向存储写入空状态。
- 确认导入新稿会替换当前草稿，取消不替换。换浏览器、换站点或清理站点数据不能恢复。暂未提供多篇草稿箱、跨设备同步或历史版本。
- 本地 Chrome 复验命令和使用方式见 [README.md](../../README.md)。
