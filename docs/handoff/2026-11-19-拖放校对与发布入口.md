# 拖放导入、内容校对与发布入口

日期：2026-11-19  
状态：✅ 本地实现及验收完成

## 如何操作

- 把一份 UTF-8 Markdown 或 TXT 拖入左侧。确认文件能读后才询问是否替换，取消或读取失败会保留当前稿件、手填标题和图片配对。文件选择按钮使用同一套确认逻辑。
- 排版后，在右侧点「编辑正文」，把单张图片拖到正文中的插入位置。支持 PNG、JPG、WebP、GIF、AVIF，每张最多 5 MB。插入时写回 Markdown 图片引用，本次页面会话内重新排版会保留图片。
- 排版后可在预览或编辑工具区点击「一键检查内容」。检查常见错写、误重复、重复标点与超过 80 个汉字的句子。点结果中的「定位」跳到标红文字。切换平台、改稿或重新排版后可重新检查。
- 平台格式兼容提示随排版生成。正文中有对应内容时标红该文字块，外链被移除时可跳回左侧选中源稿里的对应链接。
- 「视频发布入口」包含小红书、微信视频号和抖音。选中搜狐号后，「打开创作中心」使用用户提供的完整地址。

## 实现选择和踩过的坑

- 校对留在浏览器，规则表尽量只提示能指出具体位置的问题。文本偏移绑定到实际文字节点，支持一个词跨过加粗等格式，也能分辨同一个错写的多次出现。AI 和建议采纳留待后续。
- 浏览器可以直接给一段文字绘制高亮。用这一能力标红，编辑区的内容不会因包裹或插入标签而破坏光标、撤销及复制。兼容位置优先用排版时记录的源稿范围。源稿后来改动时，只有能唯一比对到同一内容块才做位置换算。定位左侧原文时要换算 Windows 换行，因为文本框会把 `CRLF` 显示为单个换行。
- 拖入图片前先验证光标落点。代码和平台降级后受保护的正文块无法可靠写回 Markdown，工具会提示拖到普通段落，避免重新排版时丢图。
- 检查按钮最初放在画布内并常驻，占用分栏编辑的正文高度。编辑时改放在现有提示行里，未检查时结果区隐藏。按钮高度收紧后，分栏和专注模式都达到现有验收门槛。

## 验收与边界

- TypeScript 类型检查、ESLint、生产构建通过，Vitest 21 个文件、313 项测试通过。生产构建提示主包超过 500 kB 阈值，仍成功产出。
- Chrome `157.0.8103.79` 通过 `scripts/verify-ui.mjs` 和 `scripts/verify-publish-review.mjs`。覆盖文件拖放和替换取消、Windows 换行定位、图片尺寸和落点、重新排版、校对结果失效、剪贴板、撤销、发布预检和四个入口的新标签页。1440×722 下分栏和专注模式的可见正文高度分别约为 361 px 和 473 px。
- 发布链接使用浏览器拦截验证精确地址及新标签页行为。搜狐号登录后的真实落地页待账号试用。规则校对只覆盖有限模式，复杂语病需人工判断。
